# Требования к производительности будущей веб-версии TaskTracker

## 1. Загрузка данных
- Приложение не должно запрашивать у сервера и передавать на клиент объемы данных, которые не используются пользователем на текущем экране.
- Общий размер первичного бандла приложения должен быть минимизирован.

## 2. Большие списки
- Отображение списков задач численностью более 50 элементов должно производиться с использованием постраничной загрузки (pagination) или виртуализации списка.
- Поиск и сортировка больших массивов данных должны выполняться на стороне сервера.

## 3. Клиентский JavaScript
- Сложные математические вычисления и обработку массивов нельзя выполнять в основном потоке интерфейса во избежание блокировки рендеринга.
- Операции манипуляции с DOM должны быть оптимизированы и группироваться.

## 4. Медиа и вложения
- Для графических вложений и пользовательских аватаров должна быть реализована отложенная загрузка (lazy loading).
- Изображения должны предварительно сжиматься на сервере и передаваться в оптимальных веб-форматах.

## 5. Работа на слабых компьютерах
- Веб-интерфейс должен сохранять отзывчивость на устройствах с объемом оперативной памяти от 2 ГБ.
- Следует избегать тяжелых CSS-анимаций и вычислительно затратных визуальных эффектов.

## 6. Проверка производительности
- Производительность ключевых страниц системы должна регулярно измеряться с помощью встроенных инструментов профилирования.
